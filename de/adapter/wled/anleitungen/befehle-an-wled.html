JSON- und HTTP-Befehle senden ​

Wie sende ich einen kompletten JSON-Befehl an WLED aus ioBroker? ​

Kurz: Schreib den JSON-Befehl als Text in wled.0.<Gerät>.action, zum Beispiel {"on":true,"bri":128,"seg":[{"id":0,"fx":9}]}. Der Adapter schickt ihn unverändert an die JSON-API des Geräts. Das ist der empfohlene Weg, wenn du mehrere Werte auf einmal ändern willst.

So gehst du vor ​

  1. Öffne im Objektbaum wled.0.<Gerät>.action.
  2. Schreib einen gültigen JSON-Text hinein, zum Beispiel {"on":true,"bri":128}.
  3. Prüf das Ergebnis am Gerät oder an den Datenpunkten on und bri, die WLED danach zurückmeldet.

Im Skript sieht das so aus:

js
setState('wled.0.<Gerät>.action', JSON.stringify({
    on: true,
    bri: 128,
    seg: [{ id: 0, fx: 9, col: [[255, 120, 0]] }],
}));

JSON.stringify macht aus dem Objekt den Text, den action erwartet. Ein Objekt direkt in den Datenpunkt zu schreiben funktioniert nicht.

Das Format der WLED-JSON-API ​

Der Befehl ist ein Teil des Zustandsobjekts von WLED. Du schreibst nur die Werte hinein, die sich ändern sollen. Häufige Beispiele:

WasJSON
Einschalten mit halber Helligkeit{"on":true,"bri":128}
Umschalten{"on":"t"}
Preset 3 laden, auch wenn es schon aktiv war{"on":true,"ps":3}
Effekt und Palette in Segment 1{"seg":[{"id":1,"fx":9,"pal":5}]}
Primärfarbe in Segment 0{"seg":[{"id":0,"col":[[255,0,0]]}]}
In 5 Sekunden ausblenden{"on":false,"tt":50}
Nightlight, 10 Minuten{"nl":{"on":true,"dur":10,"mode":1}}

Alle Schlüssel stehen in der JSON-API-Doku von WLED. WLED selbst empfiehlt die JSON-API für neue Anbindungen und nicht mehr die ältere HTTP-API.

Was der Adapter damit macht ​

  • Er prüft nur, ob der Text gültiges JSON ist. Ist er es nicht, steht State … is not a valid JSON string als Fehler im Log und nichts wird gesendet.
  • Den Inhalt prüft er nicht. Schreibst du einen Schlüssel falsch, ignoriert WLED ihn ohne Meldung.
  • Er sendet über die WebSocket-Verbindung, wenn sie steht, sonst per HTTP-POST an http://192.168.x.y/json.

Bis v0.9.2: Über WebSocket setzt der Adapter action nie auf ack=true. Über HTTP setzt er ack=true, wenn WLED success meldet.

Ab v0.9.3: Der Adapter setzt ack=true, sobald der Befehl gesendet ist, und warnt im Log, wenn das Senden scheitert. An ein Gerät, das offline ist, sendet er nichts (#904).

action oder rawCommand? ​

actionrawCommand
FormatJSON, zum Beispiel {"bri":128}HTTP-Parameter, zum Beispiel A=128
API von WLEDJSON-API (/json)ältere HTTP-API (/win)
Segmente, Presets, einzelne LEDsjanur eingeschränkt
VerbindungWebSocket oder HTTPimmer HTTP

Nimm action, wann immer es geht. rawCommand ist für Befehle gedacht, die du schon als HTTP-API-Text hast, siehe Wie sende ich rohe WLED-HTTP-API-Befehle (rawCommand)?.

NOTE

action gibt es ab Adapter-Version 0.8.0. Fehlt der Datenpunkt bei dir, aktualisiere den Adapter.

Ab v0.10.0: Kommt action kurz nach anderen Schreibzugriffen auf dasselbe Gerät, fasst der Adapter alles zu einem Befehl zusammen. Werte aus action überschreiben dabei gleichnamige Werte, die vorher geschrieben wurden (#926).

Wie sende ich JSON per Skript (axios oder httpPost) direkt an WLED? ​

Kurz: Im JavaScript-Adapter schickst du das JSON mit httpPost oder axios an http://192.168.x.y/json/state. Einfacher und robuster ist es aber, denselben JSON-Text in wled.0.<Gerät>.action zu schreiben. Dann sendet der Adapter, und du brauchst die IP-Adresse im Skript nicht.

Mit httpPost ​

httpPost gibt es im JavaScript-Adapter ab Version 7.9.0. Es schickt ein Objekt als JSON:

js
httpPost('http://192.168.x.y/json/state', { on: true, bri: 128, seg: [{ id: 0, fx: 9 }] }, (error, response) => {
    if (error) {
        log(`WLED nicht erreichbar: ${error}`, 'warn');
        return;
    }
    log(`Antwort: ${JSON.stringify(response.data)}`);
});

WLED antwortet mit {"success":true}. Schickst du "v":true mit, kommt stattdessen der ganze neue Zustand zurück.

Mit axios ​

axios ist im JavaScript-Adapter schon geladen, du musst es nicht installieren:

js
const axios = require('axios');

async function wled(befehl) {
    try {
        const antwort = await axios.post('http://192.168.x.y/json/state', befehl, { timeout: 3000 });
        return antwort.data;
    } catch (error) {
        log(`WLED nicht erreichbar: ${error.message}`, 'warn');
    }
}

wled({ on: true, bri: 128 });

Wann der Weg über den Adapter besser ist ​

Mit setState('wled.0.<Gerät>.action', JSON.stringify(befehl)) erreichst du dasselbe. Das hat Vorteile:

  • Keine IP im Skript. Der Adapter kennt die Adresse des Geräts und hat sie am Geräteobjekt gespeichert. Du sprichst das Gerät nur über seine ID an.
  • Bestehende Verbindung. Der Adapter nutzt die WebSocket-Verbindung, die ohnehin offen ist. Ein eigener HTTP-Aufruf ist eine zusätzliche Verbindung zum Gerät.
  • Einheitliche Fehlerbehandlung. Ab v0.9.3 verwirft der Adapter Befehle an Geräte, die offline sind, mit einer klaren Warnung im Log (#904).

Den direkten Weg brauchst du nur, wenn du die Antwort von WLED auswerten willst oder einen anderen Endpunkt als /json/state ansprichst.

NOTE

Auch wenn du direkt an WLED sendest, aktualisiert der Adapter seine Datenpunkte. Ist er per WebSocket verbunden, meldet WLED ihm jede Änderung von selbst, egal woher sie kommt. Ohne WebSocket kommt die Änderung mit der nächsten Abfrage.

Wie sende ich rohe WLED-HTTP-API-Befehle (rawCommand)? ​

Kurz: Schreib die Parameter der WLED-HTTP-API als Text in wled.0.<Gerät>.rawCommand, zum Beispiel A=128&FX=0&R=255&G=0&B=0. Der Adapter ruft damit http://192.168.x.y/win?… am Gerät auf. Für neue Skripte ist der JSON-Weg über action besser, rawCommand ist für fertige HTTP-API-Befehle gedacht.

So gehst du vor ​

  1. Öffne im Objektbaum wled.0.<Gerät>.rawCommand.
  2. Schreib die Parameter ohne Adresse und ohne win hinein, getrennt mit &, zum Beispiel A=255&T=1.
  3. Kurz danach liest der Adapter das Gerät neu ein, und die Datenpunkte zeigen den neuen Zustand.

Im Skript:

js
// einschalten, volle Helligkeit, Effekt 0 (Solid), Farbe rot
setState('wled.0.<Gerät>.rawCommand', 'T=1&A=255&FX=0&R=255&G=0&B=0');

Häufige Parameter ​

ParameterWirkung
T=0, T=1, T=2Aus, Ein, Umschalten
A=0 bis A=255Helligkeit
R=, G=, B=, W=Primärfarbe Rot, Grün, Blau, Weiß (0 bis 255)
FX=Effekt (Nummer)
SX=, IX=Geschwindigkeit und Intensität des Effekts
FP=Palette (Nummer)
PL=Preset laden (Nummer)
NL=Nightlight für so viele Minuten

Alle Parameter stehen in der HTTP-API-Doku von WLED. Unbekannte Parameter oder ungültige Werte ignoriert WLED ohne Meldung.

Was bei Fehlern passiert ​

  • Der Adapter sendet rawCommand immer per HTTP, auch wenn die WebSocket-Verbindung steht.
  • Findet er das Gerät im Objektbaum nicht, steht Device IP not found for <MAC> als Fehler im Log.
  • Ist das Gerät nicht erreichbar, steht die Fehlermeldung der HTTP-Anfrage im Log.

Bis v0.9.2: Der Adapter setzt rawCommand immer auf ack=true, auch wenn die Anfrage gescheitert ist. Der Fehler steht als Failed to send raw command: … im Log. Am Datenpunkt siehst du also nicht, ob der Befehl ankam.

Ab v0.9.3: ack=true kommt nur, wenn das Gerät geantwortet hat. Scheitert die Anfrage, bleibt ack=false, und im Log steht die Warnung Failed to send raw command to 192.168.x.y: … (#908).

Ab v0.10.0: Warten noch gebündelte Befehle an dasselbe Gerät, schickt der Adapter sie vor dem rawCommand ab. Die Reihenfolge bleibt so erhalten (#926).

TIP

Fast alles, was die HTTP-API kann, geht auch als JSON über action, zum Beispiel {"on":true,"bri":255,"seg":[{"id":0,"fx":0,"col":[[255,0,0]]}]}. Einzelne LEDs gehen nur dort, und Segmente sprichst du dort einfacher über ihre Nummer an.
