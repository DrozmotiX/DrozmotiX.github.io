Skripte mit Blockly und JavaScript ​

Wie steuere ich WLED per JavaScript, regelmäßig oder schrittweise (zum Beispiel Sonnenaufgang)? ​

Kurz: Ein Skript schreibt mit setState() in die Datenpunkte unter wled.0.<MAC> und startet sich mit schedule() zu einer Uhrzeit oder mit setInterval() in festen Abständen. Für einen weichen Verlauf wie einen Sonnenaufgang lässt du WLED die Übergänge rechnen: entweder mit dem Nightlight im Modus „Sonnenaufgang“ ganz ohne Schritte im Skript, oder mit wenigen Schritten, die jeweils eine Überblendzeit tt mitschicken.

Grundgerüst ​

javascript
const WLED = 'wled.0.<MAC>';

// Lesen: .val gehört hinter getState(), nicht in die ID
const istAn = getState(`${WLED}.on`).val;

// Schreiben: ohne drittes Argument ist das ein Steuerbefehl (ack=false)
setState(`${WLED}.bri`, 128);          // ganze Zahl 0..255

// Zu einer Uhrzeit: Montag bis Freitag um 6:30
schedule('30 6 * * 1-5', () => {
    setState(`${WLED}.on`, true);
});

Leg Funktionen, die zeitgesteuert laufen, auf oberster Ebene des Skripts an und nicht innerhalb eines on()-Auslösers. Sonst entsteht bei jedem Auslösen ein weiterer Zeitplan. Schick Zahlen als ganze Zahlen, zum Beispiel mit Math.round().

Sonnenaufgang mit dem Nightlight (ohne Schritte) ​

WLED hat einen eingebauten Sonnenaufgang: Startest du das Nightlight im Modus 3, während das Licht aus ist, fährt WLED über dur Minuten einen Sonnenaufgang hoch, höchstens 60 Minuten. Ist das Licht an, wird es ein Sonnenuntergang.

javascript
schedule('30 6 * * 1-5', () => {
    setState('wled.0.<MAC>.action', JSON.stringify({ nl: { on: true, dur: 30, mode: 3 } }));
});

Den Modus gibt es nur über action, weil nl.mode im Adapter nicht beschreibbar ist. Die übrigen Nightlight-Datenpunkte stehen unter WLED nach einer Zeit ausschalten.

Schrittweise per Skript ​

Willst du Farbe und Verlauf selbst bestimmen, schreibt das Skript in festen Abständen einen neuen Wert. Jeder Schritt schickt die Überblendzeit tt mit, damit WLED bis zum nächsten Schritt weich überblendet. So reichen wenige Schritte.

javascript
const WLED = 'wled.0.<MAC>';
const DAUER_MIN = 30;  // Gesamtdauer
const SCHRITTE = 30;   // ein Schritt pro Minute
let schritt = 0;
let ablauf = null;

function naechsterSchritt() {
    schritt++;
    const bri = Math.round(255 * schritt / SCHRITTE);
    // tt in Zehntelsekunden: 600 = 60 s weich überblenden
    setState(`${WLED}.action`, JSON.stringify({ on: true, bri, tt: 600 }));
    if (schritt >= SCHRITTE) {
        clearInterval(ablauf);
        ablauf = null;
    }
}

function starteSonnenaufgang() {
    if (ablauf) clearInterval(ablauf);
    schritt = 0;
    // Startzustand in einem Befehl: an, ganz dunkel, warmes Orange, Effekt "Solid"
    setState(`${WLED}.action`, JSON.stringify({ on: true, bri: 1, seg: { id: 0, fx: 0, col: [[255, 120, 0]] } }));
    ablauf = setInterval(naechsterSchritt, (DAUER_MIN * 60 * 1000) / SCHRITTE);
}

schedule('30 6 * * 1-5', starteSonnenaufgang);

Wie oft darf ein Skript schreiben? ​

  • Werte eines Schritts zusammen schicken. Jeder geschriebene Datenpunkt ist ein eigener Befehl an das Gerät. Gehören mehrere Werte zu einem Schritt, schick sie als ein JSON über action, wie im Beispiel.
  • Wenige Schritte mit Überblendung statt vieler kleiner. Ein Schritt pro Sekunde oder seltener reicht, den Rest erledigt tt. Schreibt ein Skript viele Befehle in kurzer Folge, kann WLED Befehle verlieren oder mit Zeitüberschreitung antworten, siehe Mehrere Befehle führen zu ETIMEDOUT.
  • tt gilt nur für den einen Befehl. Allein in wled.0.<MAC>.tt geschrieben, bewirkt es nichts, weil dann kein Wert mitkommt, der überblendet werden könnte. Dauerhaft änderst du die Überblendzeit mit wled.0.<MAC>.transition. Beide zählen in Zehntelsekunden, mehr als 655 (65,5 Sekunden) geht nicht.

Ab v0.10.0: Der Adapter bündelt Befehle an dasselbe Gerät, die innerhalb von 50 ms aufeinander folgen, zu einem Befehl. Mehrere setState() direkt hintereinander sind damit unkritisch. Bei einer Animation, deren Schritte schneller als diese Wartezeit aufeinander folgen und trotzdem einzeln ankommen sollen, schaltest du das Bündeln für das Gerät aus: false in wled.0.<MAC>.bundleCommands schreiben oder im Device Manager (in Admin 8.3 „Konfig-Manager“, in älteren Admins „Geräte“) bei „Gerät bearbeiten“ den Haken „Kurz aufeinander folgende Befehle bündeln“ entfernen (#926).

Wie finde ich WLED-Datenpunkte im Skript-Selektor über die Rolle switch.light? ​

Kurz: Die Rolle switch.light hat bei WLED nicht nur der Geräteschalter wled.0.<MAC>.on, sondern jeder Datenpunkt mit dem Namen on, also auch seg.<Segment>.on und nl.on. Ein Selektor nur auf die Rolle findet deshalb zu viel. Grenz ihn mit der Instanz in der ID ein und filtere im Skript nach der Tiefe der ID.

Der Adapter vergibt Rolle, Name und Typ nach dem letzten Teil der ID. Für alle Datenpunkte, die on heißen, gilt derselbe Eintrag mit der Rolle switch.light, egal ob sie direkt unter dem Gerät, in einem Segment oder im Nightlight liegen.

Welche Rollen die wichtigsten Datenpunkte haben ​

DatenpunktRolle
on, seg.<Segment>.on, nl.onswitch.light
bri, seg.<Segment>.brilevel.brightness
ps, pl, seg.<Segment>.fx, seg.<Segment>.palvalue
seg.<Segment>.sx, seg.<Segment>.ixlevel
transitionvalue.transition
seg.<Segment>.cctlevel.color.temperature

Die vollständige Liste steht unter Was bedeuten die einzelnen WLED-Datenpunkte.

So baust du den Selektor ​

Die ID eines Geräteschalters hat genau vier Teile: wled, Instanz, MAC und on. Segment- und Nightlight-Schalter sind länger. Daran trennst du sie:

javascript
// Alle Geräteschalter der Instanz wled.0, ohne Segmente und Nightlight
const geraete = $('state[id=wled.0.*][role=switch.light]')
    .toArray()
    .filter(id => id.split('.').length === 4);

// Zum Beispiel: alle WLED-Geräte ausschalten
geraete.forEach(id => setState(id, false));

// Oder: auf jedes Ein- und Ausschalten am Gerät reagieren
on({ id: geraete, change: 'ne', ack: true }, obj => {
    log(`${obj.id} ist jetzt ${obj.state.val ? 'an' : 'aus'}`);
});

toArray() gibt es im JavaScript-Adapter ab Version 8.2.0. Willst du nur die Segmentschalter, filterst du auf id.includes('.seg.'). Ohne Filter erwischt ein Befehl an alle Treffer auch nl.on und startet damit auf jedem Gerät das Nightlight.

In Blockly nimmst du den Block „IDs vom Selektor“ mit demselben Text state[id=wled.0.*][role=switch.light]. Das Filtern nach der Länge der ID geht dort nur über eine Schleife mit einer Abfrage, einfacher ist es, die Geräteschalter einzeln oder über eine Aufzählung (Funktion oder Raum) auszuwählen.

Ab v0.10.0: Der Adapter legt zusätzlich wled.0.<MAC>.light.on mit der Rolle switch.light an, zusammen mit light.dimmer und light.rgb für iot, Alexa und Google (#328). Diese ID hat fünf Teile, der Filter oben lässt sie also weg. Willst du stattdessen diese Lichtschalter, filterst du auf id.endsWith('.light.on').

Wie baue ich eine Garagentor-Beleuchtung mit WLED-Presets? ​

Kurz: Leg die Lichtstimmungen als Presets in WLED an und lass ein Skript nur die Preset-Nummer setzen. Das Skript leitet aus den Torkontakten ab, ob das Tor fährt, offen ist oder zu, und schaltet nach dem Schließen mit Nachlauf aus. Ein Zeitlimit etwas länger als die Fahrzeit fängt ab, dass das Tor halb offen stehen bleibt.

Das ist eine Anwendung des allgemeinen Musters aus Presets per Automatik schalten: Sensor löst aus, Skript setzt ps, nach Ablauf geht es zurück. Der Adapter schickt jeden Steuerbefehl sofort an das Gerät, die ganze Torlogik liegt im Skript.

Was du vorbereitest ​

  1. Presets in WLED: zum Beispiel Nummer 11 „Tor fährt“ (orangefarbenes Lauflicht) und Nummer 12 „Tor offen“ (helles Arbeitslicht). Speichere beide bei eingeschaltetem Licht mit „Include brightness“.
  2. Kontakte: Am besten zwei Kontakte, einer meldet „Tor ist zu“, der andere „Tor ist ganz offen“. Such ihre IDs im Objektbaum heraus und prüf, bei welchem Zustand sie true melden.
  3. Zeiten: Miss, wie lange das Tor von einer Endlage zur anderen braucht, und gib ein paar Sekunden dazu. Leg fest, wie lange das Licht nach dem Schließen an bleiben soll.
KontakteZustandLicht
„zu“ wird falseTor öffnetPreset 11, Zeitlimit startet
„offen“ wird trueTor ist offenPreset 12
„offen“ wird falseTor schließtPreset 11, Zeitlimit startet
„zu“ wird trueTor ist zuPreset 12, nach dem Nachlauf aus
Zeitlimit abgelaufen, keine EndlageTor steht halb offenPreset 12

Beispiel in JavaScript ​

javascript
const WLED = 'wled.0.<MAC>';
const KONTAKT_ZU = '<ID Kontakt Tor zu>';       // true = Tor ist geschlossen
const KONTAKT_OFFEN = '<ID Kontakt Tor offen>'; // true = Tor ist ganz offen
const PRESET_FAEHRT = 11;
const PRESET_OFFEN = 12;
const FAHRZEIT_MS = 25 * 1000;      // etwas länger als die Fahrzeit des Tors
const NACHLAUF_MS = 2 * 60 * 1000;  // Licht nach dem Schließen

let fahrTimer = null;
let nachlauf = null;

function stoppeTimer() {
    if (fahrTimer) { clearTimeout(fahrTimer); fahrTimer = null; }
    if (nachlauf) { clearTimeout(nachlauf); nachlauf = null; }
}

// Einschalten und Preset in einem Befehl, wirkt auch, wenn das Preset schon aktiv war
function setzePreset(nummer) {
    setState(`${WLED}.action`, JSON.stringify({ on: true, ps: nummer }));
}

// Tor verlässt eine Endlage
function torFaehrt() {
    stoppeTimer();
    setzePreset(PRESET_FAEHRT);
    fahrTimer = setTimeout(() => {
        fahrTimer = null;
        setzePreset(PRESET_OFFEN); // keine Endlage erreicht: Tor steht halb offen
    }, FAHRZEIT_MS);
}

// Ein Auslöser je Kontakt
on({ id: KONTAKT_ZU, change: 'ne' }, obj => {
    if (obj.state.val) {
        stoppeTimer();
        setzePreset(PRESET_OFFEN);
        nachlauf = setTimeout(() => {
            nachlauf = null;
            setState(`${WLED}.on`, false);
        }, NACHLAUF_MS);
    } else {
        torFaehrt(); // öffnet
    }
});

on({ id: KONTAKT_OFFEN, change: 'ne' }, obj => {
    if (obj.state.val) {
        stoppeTimer();
        setzePreset(PRESET_OFFEN);
    } else {
        torFaehrt(); // schließt
    }
});

Hast du nur einen Kontakt für „Tor ist zu“, lass den zweiten Auslöser weg. Das Öffnen erkennst du dann, das Schließen erst, wenn das Tor zu ist. Nach dem Zeitlimit zeigt das Licht „offen“, bis der Kontakt „zu“ meldet.

Willst du den Torzustand auch in VIS anzeigen, schreib ihn im Skript zusätzlich in einen eigenen Datenpunkt unter 0_userdata.0, zum Beispiel mit den Werten zu, faehrt, offen und halb.

Beispiel in Blockly ​

  1. Block „Falls Objekt“ auf den Kontakt „zu“, „wurde geändert“.
  2. Ist der Wert wahr: zuerst „stop“ für die Verzögerungen „fahrt“ und „nachlauf“, dann „steuere“ wled.0.<MAC>.action mit dem Text {"on":true,"ps":12}. Danach „Ausführen“ mit dem Namen „nachlauf“ „in“ 2 Min, darin „steuere“ wled.0.<MAC>.on mit falsch.
  3. Ist der Wert falsch: „stop“ für beide Verzögerungen, „steuere“ action mit {"on":true,"ps":11}, dann „Ausführen“ mit dem Namen „fahrt“ „in“ 25 Sek, darin „steuere“ action mit {"on":true,"ps":12}.
  4. Einen zweiten Block „Falls Objekt“ für den Kontakt „offen“: bei wahr „stop“ für beide Verzögerungen und {"on":true,"ps":12}, bei falsch dasselbe wie in Schritt 3.

Worauf du achten solltest ​

  • Ein Auslöser je Kontakt. Mehrere Auslöser auf denselben Kontakt stören sich gegenseitig. Alles, was zu einem Kontakt gehört, kommt in einen Block.
  • Kein „Pause“-Block. Verzögerungen nur mit „Ausführen … in“ und „stop“, sonst lässt sich ein Ablauf nicht abbrechen, wenn das Tor die Richtung wechselt.
  • Gerät offline: Ist WLED gerade nicht verbunden, geht der Befehl verloren. Ab v0.9.3 steht dann eine Warnung „Device … is offline, command for … discarded“ im Log (#904). Ab v0.10.0: Ein Befehl an ein Gerät, das offline gilt, löst sofort einen Verbindungsversuch aus und geht durch, wenn das Gerät wieder erreichbar ist (#939).

Wie schalte ich WLED nach einer Zeit automatisch aus (Timer)? ​

Kurz: Es gibt zwei Wege. Entweder startet dein Skript beim Einschalten einen Timer und schreibt nach Ablauf false in wled.0.<MAC>.on. Oder du nutzt das Nightlight von WLED (nl): Dann zählt das Gerät selbst herunter und schaltet aus, auch wenn ioBroker in der Zeit nicht läuft.

Ausschalten ist für den Adapter ein ganz normaler Schreibzugriff auf on. Die Zeitlogik gehört ins Skript. Wichtig ist, einen laufenden Timer beim erneuten Auslösen zu löschen und neu zu starten, statt mit Pausen zu arbeiten.

Timer in Blockly ​

  1. Leg einen Block „Falls Objekt“ an und wähl als Objekt wled.0.<MAC>.on. Stell „wurde geändert“ ein.
  2. Prüf im Block, ob der Wert wahr ist.
  3. Setz darin den Block „steuere“ für wled.0.<MAC>.on mit dem Wert falsch. Aktiviere „mit Verzögerung“, gib die Zeit an (zum Beispiel 10 Min) und hak „löschen falls läuft“ an.
  4. Damit startet jedes neue Einschalten den Timer von vorn. Ein Ausschalten von Hand vor Ablauf schadet nicht: Dann schreibt der Timer false auf ein Licht, das schon aus ist.

Timer in JavaScript ​

javascript
const WLED = 'wled.0.<MAC>';
const DAUER_MS = 10 * 60 * 1000; // 10 Minuten
let ausTimer = null;

// WLED meldet: Licht ist an (egal ob per VIS, App oder Taster eingeschaltet)
on({ id: `${WLED}.on`, val: true, change: 'ne', ack: true }, () => {
    if (ausTimer) clearTimeout(ausTimer); // laufenden Timer neu starten
    ausTimer = setTimeout(() => {
        ausTimer = null;
        setState(`${WLED}.on`, false); // Steuerbefehl (ack=false)
    }, DAUER_MS);
});

// Wird von Hand ausgeschaltet, ist der Timer überflüssig
on({ id: `${WLED}.on`, val: false, change: 'ne', ack: true }, () => {
    if (ausTimer) clearTimeout(ausTimer);
    ausTimer = null;
});

ack: true im Auslöser bedeutet: Das Skript reagiert auf die Rückmeldung vom Gerät, nicht auf deinen eigenen Befehl. change: 'ne' sorgt dafür, dass nur eine echte Änderung den Timer startet.

WARNING

Bis v0.9.2 setzt der Adapter on auf false, sobald ein Gerät offline geht, und beim Adapterstart. Ein Skript, das auf on reagiert, wird dadurch auch ohne echtes Schalten ausgelöst. Ab v0.9.3: on und bri behalten beim Offline-Gehen und beim Start ihren letzten Wert, die echten Werte kommen beim Wiederverbinden vom Gerät (#899).

Ist das Gerät offline, wenn der Timer abläuft, kommt der Befehl nicht an. Der Adapter puffert nichts. Ab v0.9.3 steht dann eine Warnung „Device … is offline, command for … discarded“ im Log (#904). Wenn das Ausschalten sicher klappen muss, nimm das Nightlight.

Timer mit dem WLED-Nightlight ​

Das Nightlight läuft im Gerät. Der Adapter legt dafür unter wled.0.<MAC>.nl diese Datenpunkte an:

DatenpunktBedeutungSchreibbar
nl.onNightlight starten (true) oder abbrechen (false)ja
nl.durLaufzeit in Minuten, 1 bis 255ja
nl.tbriZielhelligkeit am Ende, 0 bis 255; bei 0 ist das Licht danach ausja
nl.modeArt: 0 sofort, 1 langsam dimmen, 2 Farbe überblenden, 3 Sonnenaufgangnein, nur über action
nl.remRestzeit in Sekunden, -1 wenn kein Nightlight läuftnein

So schaltest du das Licht in 10 Minuten aus:

  1. Schreib 10 in wled.0.<MAC>.nl.dur und 0 in wled.0.<MAC>.nl.tbri.
  2. Schalte das Licht ein, falls es aus ist, und schreib dann true in wled.0.<MAC>.nl.on.
  3. Nach Ablauf setzt WLED die Helligkeit auf nl.tbri, also aus. nl.on geht wieder auf false.

Den Modus kannst du nur über den Datenpunkt action setzen, weil nl.mode im Adapter nicht schreibbar ist. Mit einem einzigen Befehl schaltest du ein und lässt das Licht über 10 Minuten langsam ausdimmen:

json
{"on":true,"nl":{"on":true,"dur":10,"mode":1,"tbri":0}}

In JavaScript: setState('wled.0.<MAC>.action', JSON.stringify({ on: true, nl: { on: true, dur: 10, mode: 1, tbri: 0 } }));. In Blockly schreibst du denselben Text mit „steuere“ in action.

Wie zeige ich Status oder Countdown auf dem Streifen an? ​

Kurz: Eine fertige Statusanzeige hat der Adapter nicht, du baust sie im Skript aus drei Bausteinen: ein Preset je Zustand (zum Beispiel grün, gelb, rot blinkend), ein eigenes Segment für die Anzeige, wenn der Rest des Streifens normal leuchten soll, und für Countdowns der Effekt „Percent“, dessen Balken du über seg.<Segment>.ix verkürzt.

Das Skript wertet die Quelle aus, zum Beispiel einen Sensor, einen Alarm, PRTG oder einen Alexa-Timer, und schreibt dann Preset, Farbe oder Effekt. Der Adapter gibt diese Werte nur an WLED weiter.

Status per Preset ​

  1. Leg in WLED je Zustand ein Preset an, zum Beispiel 21 „OK“ (grün), 22 „Warnung“ (gelb), 23 „Fehler“ (rot, Effekt „Blink“).
  2. Lass das Skript bei jeder Änderung der Quelle das passende Preset setzen:
javascript
const WLED = 'wled.0.<MAC>';
const QUELLE = '<ID des Status-Datenpunkts>';   // z. B. 0 = OK, 1 = Warnung, 2 = Fehler
const PRESET = { 0: 21, 1: 22, 2: 23 };

on({ id: QUELLE, change: 'ne' }, obj => {
    const nummer = PRESET[obj.state.val];
    if (nummer) {
        setState(`${WLED}.action`, JSON.stringify({ on: true, ps: nummer }));
    }
});

{"on":true,"ps":…} über action schaltet das Licht dabei ein und lädt das Preset auch dann, wenn es vorher schon aktiv war und das Licht nur aus war.

Status nur auf einem Teil des Streifens ​

Soll nur ein Stück des Streifens den Status zeigen, zum Beispiel die letzten zehn LEDs, leg dafür in WLED ein eigenes Segment an. Dann schreibst du nur in dieses Segment:

javascript
// Segment 1 rot blinken lassen, Segment 0 bleibt, wie es ist
setState('wled.0.<MAC>.action', JSON.stringify({ seg: { id: 1, on: true, fx: 1, col: [[255, 0, 0], [0, 0, 0]] } }));

Presets für ein solches Segment speicherst du in WLED mit „Checked segments only“. Dann ändert das Preset nur das angehakte Segment. Wie du Segmente anlegst, steht unter Segmente aus ioBroker anlegen.

Countdown als schrumpfender Balken ​

Der Effekt „Percent“ zeigt einen Balken, dessen Länge ix in Prozent angibt. Für einen Countdown setzt das Skript den Balken am Anfang auf 100 und verkürzt ihn in festen Abständen. Am Ende blinkt das Segment rot.

javascript
const WLED = 'wled.0.<MAC>';
let countdown = null;

function starteCountdown(sekunden) {
    if (countdown) clearInterval(countdown);
    const ende = Date.now() + sekunden * 1000;
    // Percent (98), Palette "* Color 1" (2), blauer Balken, Rest aus; sx 64 lässt den Balken gleiten
    setState(`${WLED}.action`, JSON.stringify({
        on: true,
        seg: { id: 0, fx: 98, pal: 2, sx: 64, ix: 100, col: [[0, 0, 255], [0, 0, 0]] },
    }));
    countdown = setInterval(() => {
        const rest = Math.max(0, ende - Date.now());
        setState(`${WLED}.seg.0.ix`, Math.round((rest / (sekunden * 1000)) * 100));
        if (rest === 0) {
            clearInterval(countdown);
            countdown = null;
            setState(`${WLED}.action`, JSON.stringify({ seg: { id: 0, fx: 1, col: [[255, 0, 0], [0, 0, 0]] } }));
        }
    }, 5000); // alle 5 Sekunden
}

starteCountdown(10 * 60); // zum Beispiel 10 Minuten

Alle paar Sekunden ein neuer Wert reicht, sx lässt den Balken dazwischen weich laufen. Was die Werte von „Percent“ genau bewirken, steht unter Effekt „Percent“ als Balken.

TIP

Soll nach der Anzeige wieder das Licht von vorher kommen, sichere den Zustand vorher. Wie das geht, steht unter Zustand speichern und wiederherstellen.

Wie schalte ich WLED-Presets per Automatik, zum Beispiel per Bewegungsmelder? ​

Kurz: Das Muster ist immer gleich: Ein Sensor-Datenpunkt löst das Skript aus, das Skript schreibt die Preset-Nummer in wled.0.<MAC>.ps, und nach einer Nachlaufzeit schaltet es auf ein anderes Preset zurück oder schreibt false in on. Das funktioniert mit Bewegungsmeldern, Tür- und Torkontakten oder jedem anderen State.

Der Adapter macht dabei nichts Besonderes: Jeder Schreibzugriff mit ack=false auf ps oder on wird sofort an das Gerät geschickt. Die Logik, wann welches Preset gilt, liegt ganz im Skript.

Was du vorbereitest ​

  1. Leg in WLED die Presets an, zum Beispiel Nummer 2 für „Bewegung“ und Nummer 1 für „Grundlicht“. Speichere das Preset für „Bewegung“ bei eingeschaltetem Licht mit „Include brightness“, damit es auch dann einschaltet, wenn das Licht vorher aus war.
  2. Such im Objektbaum die ID deines Sensors heraus, zum Beispiel den Bewegungs-State eines Zigbee- oder Homematic-Melders. Er sollte bei Bewegung true und danach false melden.
  3. Leg fest, wie lange das Licht nach der letzten Bewegung bleiben soll.

Wie ps genau funktioniert und warum ein Preset ein- oder ausschaltet, steht unter Presets per Datenpunkt ps schalten.

Beispiel in JavaScript ​

javascript
const WLED = 'wled.0.<MAC>';
const SENSOR = '<ID des Bewegungsmelders>';
const PRESET_BEWEGUNG = 2;
const PRESET_ZURUECK = 1;      // 0 bedeutet: danach ausschalten
const NACHLAUF_MS = 2 * 60 * 1000; // 2 Minuten nach der letzten Bewegung

let nachlauf = null;

// Bewegung erkannt: Preset sofort setzen, laufenden Nachlauf abbrechen
on({ id: SENSOR, val: true, change: 'ne' }, () => {
    if (nachlauf) { clearTimeout(nachlauf); nachlauf = null; }
    setState(`${WLED}.ps`, PRESET_BEWEGUNG);
});

// Keine Bewegung mehr: Nachlauf starten, danach zurückschalten
on({ id: SENSOR, val: false, change: 'ne' }, () => {
    if (nachlauf) clearTimeout(nachlauf);
    nachlauf = setTimeout(() => {
        nachlauf = null;
        if (PRESET_ZURUECK > 0) {
            setState(`${WLED}.ps`, PRESET_ZURUECK);
        } else {
            setState(`${WLED}.on`, false);
        }
    }, NACHLAUF_MS);
});

Beispiel in Blockly ​

  1. Block „Falls Objekt“ auf den Sensor, „wurde geändert“.
  2. Darin eine Abfrage auf den Wert. Ist er wahr: zuerst den Block „stop“ aus der Gruppe „Timeouts“ für die Verzögerung „nachlauf“, danach „steuere“ wled.0.<MAC>.ps mit 2.
  3. Ist er falsch: ebenfalls zuerst „stop“ für „nachlauf“, dann den Block „Ausführen“ mit dem Namen „nachlauf“ und „in“ 2 Min. Darin „steuere“ wled.0.<MAC>.ps mit 1 (oder wled.0.<MAC>.on mit falsch).
  4. So bricht jede neue Bewegung den Nachlauf ab, und jedes Ende einer Bewegung startet ihn neu. Der Block „Pause“ ist dafür nicht geeignet, weil er sich nicht abbrechen lässt.

Worauf du achten solltest ​

  • Ein Auslöser je Datenpunkt. Leg für jeden Sensor nur einen Auslöser an und lass ihn eine gemeinsame Funktion aufrufen. Mehrere Auslöser auf denselben State können sich gegenseitig stören.
  • Mehrere Sensoren (zum Beispiel Treppe oben und unten): Bestimme in einer Hilfsfunktion aus allen Sensoren, welches Preset gelten soll, und schreib ps nur dort. Eine Sperrvariable je Sensor verhindert, dass ein Ablauf den anderen abbricht.
  • Dasselbe Preset noch einmal: Ist das Preset schon aktiv, lädt WLED es nicht neu. Hast du das Licht zwischendurch über on ausgeschaltet, bleibt es deshalb aus. Schick in dem Fall {"on":true,"ps":2} an wled.0.<MAC>.action.
  • Gerät offline: Befehle an ein Gerät, das der Adapter für offline hält, kommen nicht an. Der Adapter puffert nichts. Ab v0.9.3 steht dann „Device … is offline, command for … discarded“ als Warnung im Log (#904).

TIP

Soll das Licht nach dem Nachlauf in den Zustand von vorher zurück, merk dir beim Auslösen den Wert von ps und schreib ihn danach zurück. Das klappt nur, wenn vorher ein Preset aktiv war. Zeigt ps den Wert -1, war keines aktiv.

Ein ausführliches Beispiel für ein Garagentor mit mehreren Zuständen steht unter Garagentor-Beleuchtung mit WLED-Presets.

Wie speichere ich den Zustand und stelle ihn nach einer Animation wieder her? ​

Kurz: Am sichersten lässt du WLED den Zustand selbst sichern: Vor der Animation {"psave":250,"ib":true,"sb":true} an wled.0.<MAC>.action schicken, danach {"ps":250}. Alternativ merkt sich dein Skript die Preset-Nummer aus ps oder die einzelnen Datenpunkte und schreibt sie danach zurück. Der Adapter hat im Grundstand v0.9.2 keine eigene Funktion dafür.

Weg 1: Zustand in WLED als Preset sichern ​

WLED speichert mit psave den aktuellen Zustand als Preset: Farben, Effekt, Palette und Effekt-Werte aller Segmente. Mit ib kommen Ein/Aus und Helligkeit dazu, mit sb die Segmentgrenzen.

javascript
const WLED = 'wled.0.<MAC>';
const ZWISCHENSPEICHER = 250; // ein Preset-Platz, den du sonst nicht nutzt

async function mitAnimation(animation) {
    // 1. Zustand sichern
    setState(`${WLED}.action`, JSON.stringify({ psave: ZWISCHENSPEICHER, ib: true, sb: true }));
    await wait(1000); // WLED speichert nicht sofort, kurz warten
    // 2. Animation abspielen
    await animation();
    // 3. Zustand zurückholen
    setState(`${WLED}.action`, JSON.stringify({ ps: ZWISCHENSPEICHER }));
}

// Beispiel: 5 Sekunden rot blinken
mitAnimation(async () => {
    setState(`${WLED}.action`, JSON.stringify({ on: true, bri: 255, seg: { id: 0, fx: 1, col: [[255, 0, 0], [0, 0, 0]] } }));
    await wait(5000);
});

Darauf kommt es an:

  • ib und sb mitschicken. Schreibst du nur die Nummer in den Datenpunkt wled.0.<MAC>.psave, speichert WLED das Preset ohne Ein/Aus, Helligkeit und Segmentgrenzen. Das Licht bleibt beim Zurückholen dann so hell oder so aus, wie die Animation es hinterlassen hat.
  • Nummer 1 bis 250. Über ps lädt WLED nur Presets von 1 bis 250. Nimm einen Platz, den du sonst nicht nutzt, er wird jedes Mal überschrieben.
  • Kurz warten. WLED schreibt das Preset erst im nächsten Durchlauf seiner Hauptschleife. Startet die Animation sofort, kann schon ein Teil von ihr im Preset landen.
  • War das Licht vorher aus, ist es nach dem Zurückholen wieder aus. Genau das will man meist.

Weg 2: Preset-Nummer merken ​

War vor der Animation ein Preset aktiv, reicht es, seine Nummer zu merken: const vorher = getState('wled.0.<MAC>.ps').val; vor der Animation und danach {"on":true,"ps":vorher} an action. Zeigt ps den Wert -1, war kein Preset aktiv, dann nimm Weg 1 oder Weg 3.

Weg 3: Datenpunkte merken ​

Das Skript liest die Werte, die die Animation verändert, und schickt sie danach in einem Befehl zurück. Die Farben stehen in seg.<Segment>.col.0 bis col.2 als Text wie [255,160,0].

javascript
const WLED = 'wled.0.<MAC>';

function sichern() {
    const wert = id => getState(`${WLED}.${id}`).val;
    return {
        on: wert('on'),
        bri: wert('bri'),
        seg: {
            id: 0,
            fx: wert('seg.0.fx'),
            pal: wert('seg.0.pal'),
            sx: wert('seg.0.sx'),
            ix: wert('seg.0.ix'),
            col: [0, 1, 2].map(n => JSON.parse(wert(`seg.0.col.${n}`))),
        },
    };
}

const gesichert = sichern();
// ... Animation ...
setState(`${WLED}.action`, JSON.stringify(gesichert));

Die Werte in ioBroker sind nur so aktuell wie die letzte Rückmeldung des Geräts. Über WebSocket kommt sie sofort, ohne WebSocket erst bei der nächsten Abfrage. Hat das Gerät mehrere Segmente, sicherst du jedes, das die Animation ändert.

Ab v0.10.0: die letzte Änderung per Knopf zurücknehmen ​

Ab v0.10.0: Unter wled.0.<MAC>.seg.<Segment>.last merkt sich der Adapter Farben (last.col), Effekt (last.fx) und Palette (last.pal) von vor der letzten Änderung. Schreibst du true in den Knopf last.restore, schickt er diese Werte wieder an das Segment (#930).

Das passt, wenn ein Hinweis Farbe oder Effekt einmal umschaltet. Für eine Animation mit mehreren Schritten passt es nicht: Es zählt nur die letzte Änderung, last.* enthält danach den vorletzten Schritt und nicht den Zustand vor der Animation. Ein/Aus, Helligkeit und Effekt-Werte wie sx und ix sind nicht dabei. Für den ganzen Zustand nimmst du weiter Weg 1.

Woran erkenne ich, ob WLED per Telegram, VIS oder Web-Oberfläche geschaltet wurde? ​

Kurz: WLED meldet nicht, wer geschaltet hat. Unterscheiden kannst du nur zwei Fälle: Ein Befehl aus ioBroker (Telegram, VIS, Skript, Admin) kommt als Steuerbefehl mit ack=false an und trägt im Merkmal from die Instanz, die ihn geschrieben hat. Eine Änderung am Gerät selbst (WLED-Oberfläche, App, Taster, Sync) kommt nur als Rückmeldung mit ack=true vom WLED-Adapter.

Was der Adapter liefert ​

Wer schaltetackfrom
Skript, Telegram, VIS, Admin oder ein anderer Adaptererst false, nach dem Senden truebeim Befehl die schreibende Instanz, zum Beispiel system.adapter.telegram.0 oder system.adapter.javascript.0; danach system.adapter.wled.0
WLED-Oberfläche, WLED-App, Taster, Infrarot, UDP-Sync oder Sprachsteuerung direkt in WLEDnur truesystem.adapter.wled.0

Die Quelle des Befehls siehst du also nur im Moment des Steuerbefehls. Sobald der Adapter den Befehl bestätigt oder das Gerät seinen neuen Zustand meldet, steht dort system.adapter.wled.0. Für Änderungen am Gerät gibt es kein Merkmal, das WLED-Oberfläche, App oder Taster unterscheidet.

Ab v0.9.3: Auch über WebSocket bestätigt der Adapter einen gesendeten Befehl sofort mit ack=true (#904). Bis v0.9.2 kommt das ack=true dort erst mit der Rückmeldung des Geräts.

Umweg: den Steuerbefehl abfangen ​

Ein Auslöser auf ack=false sieht jeden Befehl aus ioBroker mit seiner Quelle. Ein zweiter Auslöser auf ack=true erkennt Änderungen, denen kein Befehl aus ioBroker vorausging. Die kamen dann vom Gerät selbst.

javascript
const ON = 'wled.0.<MAC>.on';
const QUELLE = '0_userdata.0.wledQuelle'; // selbst angelegter Text-Datenpunkt
let letzterBefehl = 0;

// Befehl aus ioBroker: Quelle steht in from
on({ id: ON, ack: false }, obj => {
    letzterBefehl = Date.now();
    setState(QUELLE, obj.state.from.replace('system.adapter.', ''), true);
});

// Rückmeldung vom Gerät ohne vorherigen Befehl: am Gerät geschaltet
on({ id: ON, ack: true, change: 'ne' }, () => {
    if (Date.now() - letzterBefehl > 5000) {
        setState(QUELLE, 'WLED direkt (Oberfläche, App, Taster)', true);
    }
});

In Blockly wählst du im Block „Falls Objekt“ bei „Auslösung durch“ den Eintrag „unbestätigte Änderung“ und liest die Quelle mit „Nehme Ursprung von Trigger“.

Die 5 Sekunden sind ein Puffer für die Antwortzeit des Geräts. Ohne WebSocket kommt die Rückmeldung erst bei der nächsten Abfrage, dann muss der Puffer länger sein als das Abfrageintervall.

TIP

Schalten Telegram oder VIS über eigene Skripte, ist es einfacher, dort zusätzlich einen eigenen Datenpunkt „zuletzt geschaltet von“ zu setzen. Dann hängt nichts an Zeitfenstern.

NOTE

Die Datenpunkte _info.live, _info.lm und _info.lip zeigen, ob WLED gerade Echtzeitdaten empfängt (zum Beispiel per E1.31 oder UDP aus Hyperion oder xLights), welcher Art und von welcher Adresse. Mit lor übersteuerst du diese Daten. Wer das Licht ein- oder ausgeschaltet hat, sagen sie nicht.
